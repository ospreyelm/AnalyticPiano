Login sequence
1. User visits /accounts/login/ → redirected to clerk.harmonylab.com/sign-in
2. User signs in via email, Google, or Apple (Clerk handles UI)
3. Clerk issues a JWT → stored in browser cookie
4. Every Django request: middleware validates JWT → looks up User by clerk_user_id
5. request.user is the Django User instance — all existing views unchanged
New user signup
1. Clerk webhook fires user.created event → hits /accounts/clerk-webhook/
2. Django creates User(email=..., clerk_user_id=...) row
Preferences, groups, performance data all attach to this row as normal
What changes
  • Add clerk_user_id field to User model
  • New ClerkAuthMiddleware validates JWT
  • Webhook endpoint creates new users
  • Login/register templates → Clerk hosted pages
  • New harmony/settings/fly.py
  • Dockerfile + fly.toml
What stays the same
  • All 65 @login_required decorators
  • User model fields (preferences, groups…)
  • PerformanceData, Group, Exercise models
  • Dashboard and exercise views
  • All existing URLs
  • Admin panel
