Fly.io Deployment Design

Four new files + env vars. Existing app code unchanged.

New files

Dockerfile
Python 3.12 slim base
Install Pipfile deps via pipenv install --system
Collect static files at build time
Expose port 8000, run gunicorn
fly.toml
App name, region (ord = Chicago)
Port 8000, HTTP health check on /
[deploy] release_command runs migrations + createcachetable
1 shared-cpu-1x machine (upgradeable)
harmony/settings/fly.py
Inherits from common.py (mirrors heroku.py)
DEBUG = False, SSL redirect, secure cookies
SECRET_KEY, ALLOWED_HOSTS, DATABASE_URL from env
Sentry integration (optional)
.dockerignore
Exclude .git, db.sqlite3, .env, __pycache__,
*.pyc, local data files, scratch files

Environment variables (set via fly secrets set)

DJANGO_SETTINGS_MODULE
harmony.settings.fly
SECRET_KEY
generated strong random key
ALLOWED_HOSTS
["your-app.fly.dev"] (JSON list)
DATABASE_URL
auto-set by Fly Postgres attach
EMAIL_HOST_USER
Gmail address for password reset
EMAIL_HOST_PASSWORD
Gmail app password
SENTRY_DSN
optional

Deploy sequence

1. fly launch — creates app + generates fly.toml skeleton
2. fly postgres create — provision Postgres cluster
3. fly postgres attach — sets DATABASE_URL secret automatically
4. fly secrets set ... — remaining env vars
5. fly deploy — builds Docker image, runs release_command (migrate), starts app
6. fly open — verify app loads
7. DNS: point custom domain → fly.dev (optional, post-verify)
Not in scope
  • Clerk auth (separate spec)
  • Migrating old Heroku DB (one-off task, not code)
  • Custom domain setup (DNS, post-verify)
  • S3 / media storage (WhiteNoise handles static)
  • CI/CD pipeline
Cost estimate
  • 1× shared-cpu-1x VM: ~$2–4/mo
  • Fly Postgres (1GB shared): ~$3/mo
  • Total: ~$5–7/mo
  • Free allowance may cover VM initially
