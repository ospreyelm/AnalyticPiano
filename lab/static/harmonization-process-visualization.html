Harmonization Exercise Flow

This page turns the design spec into an inspectable process: UMTO source data becomes visible bass/label slots, each slot is graded for chord correctness, then the completed phrase receives a voice-leading tier.

End-To-End Data Flow

1

Source UMTO Chorale

Use existing four-voice Bach UMTO data: voices, analysis slices, grading slices, key, meter, and source metadata.

2

Derive Harmonization Exercise

Clone the UMTO payload, set mode to harmonization, choose visible voices, and choose figured bass or Roman labels.

3

Student Plays Chord Slots

The chord bank advances per grading slice. Bass and optional soprano are locked; inner voices are supplied by the student.

4

Chord Then Voice Leading

Each slot must be chord-correct first. When all slots are correct, a phrase-level pass assigns Developing, Proficient, or Excellent.

Per-Slot Chord Gate

Completion Tier

Attempting - 50

At least one chord slot is still wrong. Voice leading is not evaluated yet.

Developing - 70

All chords are correct, but smoothness or parallel perfect intervals fail.

Proficient - 85

Chords, smoothness, and parallels pass. Doubled leading tone is the only remaining issue.

Excellent - 95

All chords are correct and the voice-leading checks all pass.

Spec Review Concerns To Resolve Before Planning

Mode routing needs a precise frontend contract. The spec says isChorale() returns false for harmonization, but current rendering relies on the chorale-like VexFlow branch for UMTO notation. The plan needs an explicit isHarmonization() render path.
Slot derivation may duplicate existing UMTO windows. The spec says slots come from analysis slices and match grading slices. The implementation should define which array is authoritative when analysis and grading offsets diverge.
Figure parsing is now the highest-risk music-theory logic. Shorthand expansion, altered intervals, local-key defaults, and accidental-only figures need focused tests before UI work.
Held-note timing is the behavioral core. The grader needs a settle window and release grace so normal MIDI asynchrony is not misread as a wrong or incomplete sonority.
Score submission does not currently carry a numeric score field. Existing reports send numerator and denominator. The plan should specify where tier score, attempt counts, accepted sonorities, and vl_score are attached.
