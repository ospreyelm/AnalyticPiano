Architecture Overview

UMTO — Universal Music Theory Object

All exercise rows stored in the Exercise.data JSON field are UMTO. Every UMTO payload has a top-level type (which data shape it uses) and a mode (how the student interacts). Score-based exercises additionally embed a full UMTO object inside score.umto.

Two fundamental interaction modes
ModeStudent actionGraderTypes that use it
playback Sees notation → plays matching notes on MIDI ChoraleGrader / ExerciseGrader umto_chorale (playback), clausula playback
identification Sees notation → clicks ? → picks answer from popup IdentificationGrader umto_chorale (id), umto_barline_placement, umto_key_signature, umto_symbolic_meter
analysis_match Sees a label → plays matching pitch (octave-flexible) ChoraleGrader (pitch-class mode) umto_chorale (analysis_match)

umto_chorale — Playback

Score-based MIDI playback

type: "umto_chorale" · mode: "playback"
ChoraleGrader
What the student does

Sees notated score (one or more voices on treble/bass/keyboard staff). Plays each note or chord in onset-window order on MIDI keyboard. Notes turn black when correctly played. Exercise advances window by window.

Grading flow
MIDI noteOn → ChoraleGrader.noteOn() → match against grading[].target_midi_pitches → CORRECT / PARTIAL / INCORRECT
Key payload fields
FieldTypeDescription
type "umto_chorale" Score-based exercise type
mode "playback" Activates ChoraleGrader onset-window path
clef "treble" | "bass" | "keyboard" Staff layout. "keyboard" = grand staff (SATB)
grading[] GradingSlice[] One entry per onset. Each holds target MIDI pitches student must play
score.umto.voices Voices (S/A/T/B) Note events. Drives rendering AND onset-window construction
analysisType string What label overlay shows above/below score (e.g. "note_name", "roman")

umto_chorale — Identification

Score-based click-to-identify

type: "umto_chorale" · mode: "identification"
IdentificationGrader
What the student does

Sees score notation with ? slots below each target onset. Clicks a slot → popup of 4–5 choices → picks the correct label. Exercises are paginated (4 problems/page by default). identMode controls whether feedback is immediate ("practice"), deferred to Submit ("submit"), or locked without color ("test").

umto_chorale — Analysis Match

Label → MIDI (octave-flexible)

type: "umto_chorale" · mode: "analysis_match"
ChoraleGrader (pitch-class)
What the student does

Sees a label (e.g. a note name like "D" or a solfège syllable like "Re") and plays the corresponding note on MIDI in any octave. Grading is pitch-class-based — octave does not matter. Contrast with playback (exact pitch) and identification (click, no MIDI).

Key structural difference from playback

Same UMTO shape, same grading slices, but ChoraleGrader checks midi % 12 instead of exact MIDI number. Analysis labels in score.umto.analysis[] are shown as the question prompt instead of the rendered score.

⬤ Real DB example — id: EA80OW
{ "type": "umto_chorale", "mode": "analysis_match", "clef": "treble", "analysisType": "note_name", "introText": "Name the notes: BWV10.7, mm.6-7, Soprano.", "allowed_answers": ["C", "D", "F", "G"], "grading": [ { "offset": 0.0, "target_midi_pitches": [74] }, // same grading[] as playback sibling EA80OV // but grader matches pitch class (74 % 12 = 2 = D) ] }

This exercise is typically generated alongside a playback sibling from the same source measure range (same grading slices, different mode).

umto_chorale — Harmonization

Figured-bass / Roman numeral realization

type: "umto_chorale" · mode: "harmonization"
HarmonizationGrader
What the student does

Sees grand staff with a bass line and figured bass (or Roman numeral) overlays. Bass voice is locked — student plays only the upper voices. At each onset window, student holds/attacks the upper voices that complete the sonority. Exercise advances window by window, giving immediate feedback per slice.

Grading logic (slice-by-slice)

At each grading slice, HarmonizationGrader checks:

  1. Locked voices present (bass pitch-class matches)
  2. All played pitch-classes are in allowedPcs (no illegal notes)
  3. All requiredUpperPcs covered
  4. Voice count within voice_count_policy [min, max]
metadata fields unique to harmonization
FieldDescription
locked_voices Voices grader provides automatically (typically ["B"])
voice_count_policy min/max/expected upper voices student must play
harmonization_target_policy.source "figured_bass" | "roman" | "analysis_slice" — which label type drives target computation
chord_settle_ms Milliseconds before a held sonority is evaluated (default 150)

Branch B — Clausula Playback

type: "umto_chorale" · mode: "playback" · tags: branch_b
ChoraleGrader
What clausulae are

Clausulae are Renaissance-era voice-leading formulas that define cadential motion. Each voice follows a three-note clausula triple (ANTecipatio–PENultima–ULTima). The system uses Z₇ arithmetic (diatonic pitch classes 0–6) to enumerate and validate all possible multi-voice combinations. These are a core pedagogical unit in HarmonyLab's Branch B curriculum (distinct from Branch A Bach chorales).

Four clausula types (from clausulae/core.py)
TypeTriple(s)SolfègeColor
Discant (0,6,0) Do–Ti–Do ■ Red
Tenor (0,1,0) (0,1,2) (2,1,0) (2,1,2) Do/Mi ↔ Re ↔ Do/Mi ■ Green
Alto (4,4,4) (4,3,2) (4,5,4) Sol–Fa–Mi etc. ■ Blue
Bass (0,4,0) Do–Sol–Do ■ Black
Cadence types (from enumerate_* in clausulae/generate.py)
TypeVoicesDescription
Simple (τ=0) 2–4 All voices move simultaneously, ANT–PEN–ULT on same grid

Clausula math: Z₇ pitch-class system explained

All clausula logic operates in Z₇ — integers mod 7 representing the seven diatonic pitch classes (0=Do, 1=Re, 2=Mi, 3=Fa, 4=Sol, 5=La, 6=Ti). No chromatic alterations, no octave numbers — just scale-step identities. This is sufficient to define voice-leading formulas because clausulae are transposable and scale-degree-based.

# clausulae/core.py SOLFEGE = { 0:"Do", 1:"Re", 2:"Mi", 3:"Fa", 4:"Sol", 5:"La", 6:"Ti" } CLAUSULAE = { "Discant": [(0, 6, 0)], # Do–Ti–Do (leading-tone resolution) "Tenor": [(0,1,0),(0,1,2),(2,1,0),(2,1,2)], # supertonic neighbor motions "Alto": [(4,4,4),(4,3,2),(4,5,4)], # Sol neighbors "Bass": [(0,4,0)], # Do–Sol–Do (octave/fifth bass) } # Validation checks (clausulae/constraints.py): # consonant_vertical(pcs) — no dissonant intervals at ULT # parallel_perfect(v1, v2) — no parallel 5ths/8ths into ULT # distinctness_ok(triples) — no two voices same triple # bass_constraint_ok(combo) — Bass always lowest at ULT
Compound clausula temporal grid

In compound cadences, the Discant voice enters half a beat late (τ=1), creating a suspension at beat 1.

Beat: 0 0.5 1 1.5 2 Early: ANT ─────────── PEN ─────────── ULT (τ=0, e.g. Bass, Tenor, Alto) Late: (π) ANT ──── PEN ── ULT (τ=1, Discant) ↑ ↑ π consonant suspension with early ANT dissonance at beat 0 (intrinsic)

π (pronounced "pi") is the passing note the late voice plays at beat 0.5, consonant with the early ANT. Valid π values are enumerated by enumerate_compound() in clausulae/generate.py.
