NCT alignment

Chordify still creates a slice at every beat. Beats absent from WiR are retained with null display content so frontend slots stay aligned with score windows while non-chord-tone beats remain hidden from students.

Gap
Root cause of NCT pollution: chordify() merges every simultaneous pitch into a vertical chord at each time slice. A passing tone (D in a C→E soprano over an E bass chord) becomes part of a "chord" that music21 may misidentify as IV, II6, or worse. The RN label for that beat is therefore wrong. Suspension chains (7-6, 4-3, 9-8) get the same treatment — the suspended note is treated as a chord tone.

RN Analysis: What music21 romanNumeralFromChord() actually does
InputProcessOutput stored
A music21.chord.Chord object at a given offset (from chordify()) Determines scale degree, quality (major/minor/dim/aug), inversion, seventh presence, applied chord target. Uses the global key for diatonic context. raw_roman_numeral = rn.figure e.g. "V7", "viio6/V", "IV6"
Chord containing a passing tone (e.g. D in C-major chord) chordify() includes the PT — result is e.g. a [C, D, E, G] chord which may be labelled as something unexpected (e.g. G7/C, Cmaj9, or random secondary) Wrong label stored in raw_roman_numeral. No flag that D is non-harmonic.
Suspension (e.g. 4-3: F held over G-B-D bass) Chord at suspension onset = [F, G, B, D] — may read as V7/IV or G9 rather than V Wrong label. No suspension flag.
Known Gaps
Gap 1: No non-chord-tone detection at any stage Both _build_roman_analysis_overrides() and analyze_chunk_skills() use chordify() which verticalizes all voices at every 8th-note grid point. Passing tones, neighbor tones, suspensions, and anticipations are all included in the vertical slices and corrupt the RN label.
Gap 2: legacy applySkillFilter path UMTO Bach playlists now use request-time taxonomy targeting through lab/views.py. The older frontend fallback still exists for legacy/non-UMTO flows and should not be treated as the source of truth for new Bach imports.
File: lab/views.py, exercise_definition.js
Gap 3: broader suspension detection deferred The importer now recognizes the Bach/WiR 8/7/4 → 8/7/3 case and stores 7/4-3. Broader suspension families still require additional look-ahead rules.
Design invariant to preserve: roman_numeral is intentionally null at import time. Targeting (which slot gets revealed as a question vs shown as context) happens at request time in generate_exercise_context. Only raw_roman_numeral is the durable record. Any NCT improvement must write into raw_roman_numeral (or a new is_non_chord_tone flag), not into roman_numeral.

# 3. Request-time targeting checks stored WiR labels against Unit 9 cumulative answers
# 4. Sort, write ExercisePlaylistOrdered rows
